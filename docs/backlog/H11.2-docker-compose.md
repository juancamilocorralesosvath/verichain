# H11.2 — Docker Compose con nginx TLS

## Especificación

- `apps/api/Dockerfile`: multi-stage, imagen final `node:<LTS>-slim`, usuario no root, solo dependencias de producción. Corre las migraciones de Prisma al arrancar.
- `apps/web/Dockerfile`: hace el build y deja los estáticos dentro de nginx.
- `docker-compose.yml`:
  - Servicios `api` (sin puertos expuestos al host) y `web` (nginx, puertos 443 y 80→redirige a 443).
  - nginx sirve la SPA (con `try_files` hacia `index.html`) y hace proxy de `/api` → `api:3000`.
  - TLS con `secrets/tls/server.{crt,key}` (montados solo lectura), solo TLS 1.2/1.3 y cabecera HSTS.
  - Volúmenes: `api-data` para la BD y `secrets/` montado solo lectura para la llave del servidor.
  - Variables desde `.env`.
- Con HTTPS la cookie lleva `secure` (`NODE_ENV=production` en el compose).
- `.dockerignore` excluye `node_modules`, `secrets` y `.env`.

## Criterios de aceptación

- [x] `docker compose up --build` → `https://localhost` carga sin advertencias (con la CA confiada) y el login funciona.
- [x] `curl -I http://localhost` → 301 a https.
- [x] `docker compose exec api id -u` ≠ 0.
- [x] La imagen no contiene `.env` ni llaves (`docker run --rm <img> ls -a`).

## Verificación

```bash
docker compose up --build -d && curl -sk https://localhost/api/salud
```

## Notas de traspaso

### Decisiones tomadas

- Imágenes `node:24-slim` (LTS) y `nginx:stable-alpine`; contexto de build = raíz del monorepo. `prisma` pasó de devDependencies a dependencies de `@bc/api` (migra al arrancar).
- `trust proxy`: `configurarApp(app, origen, { confiarEnProxy })`, activado con `TRUST_PROXY=1` (apagado por defecto: así nadie falsea su IP). nginx **sobrescribe** `X-Forwarded-For` con `$remote_addr`. Prueba: `apps/api/test/trust-proxy.test.ts`.
- nginx agrega CSP estricta (`style-src 'self'`, sin `unsafe-inline`): **H10.1 no debe usar atributos `style` en línea** ni estilos incrustados.
- La llave del servidor se monta como archivo de solo lectura (`apps/api/secrets/server-signing-key.pem` → `/run/secrets/...`); el contenedor corre con uid 1000, así que el archivo debe ser legible por ese uid (en la mayoría de equipos Linux el primer usuario es 1000).
- El seed no corre solo: `docker compose exec api node dist/auth/ejecutar-seed.js` (una vez).
- Probado a mano (Docker 29): 301 de http a https, TLS 1.1 rechazado, HSTS y CSP presentes, `/cadena` → `index.html`, uid 1000, la API sin puerto en el host, la imagen sin `.env` ni `.pem`, login como admin con cookie `HttpOnly; Secure; SameSite=Strict`.

**Comandos exactos para el README (H12.1):**

```bash
bash infra/tls/generar-ca.sh                          # CA y certificado (secrets/tls/)
cp .env.example .env                                  # completar JWT_SECRET, DATA_KEY, ADMIN_PASSWORD
npm run llaves:servidor -w @bc/api                    # llave de firma del servidor
docker compose up --build -d                          # https://localhost
docker compose exec api node dist/auth/ejecutar-seed.js   # admin inicial (una vez)
curl --cacert secrets/tls/ca.crt https://localhost/api/salud
docker compose down -v                                # limpia contenedores y la BD
```
