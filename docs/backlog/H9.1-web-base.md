# H9.1 — Web base: React + Vite, login y layout por rol

## Contexto

Diseño §7. Interfaz **funcional sin diseño elaborado**: el diseño visual es E10. Usa HTML semántico y clases simples para que E10 pueda reestilizar sin reescribir la lógica.

## Archivos

`apps/web/**` (reemplaza el README placeholder). Paquete `@bc/web`.

## Especificación

- Vite + React + TypeScript `~6.0` + React Router. Vitest + Testing Library para pruebas.
- Proxy de Vite: `/api` → `http://localhost:3000`, para que la cookie sea del mismo origen en desarrollo.
- `src/api/cliente.ts`: `fetch` con `credentials: 'include'`. Ante un 401 lleva al login. Los errores se muestran con el `mensaje` genérico de la API.
- Página Login. Contexto de sesión (`GET /api/auth/yo`). Menú según el rol, siguiendo la matriz de §7b:
  - **registrador:** Personas, Cadena, Mi llave.
  - **auditor:** Personas, Cadena, Verificar, Bitácora, Exportar.
  - **admin:** Cadena, Verificar, Bitácora, Usuarios, Llaves, Ataques.
  - **Todos, sin login:** Verificador independiente.
- Las rutas protegidas redirigen al login, y una ruta de otro rol muestra "sin permiso".
- Prohibido `dangerouslySetInnerHTML`. Agrega la regla de ESLint `react/no-danger` si usas el plugin de React.
- Mientras no exista la API de auth (H3.1), se puede simular el login con un mock en las pruebas.

## Criterios de aceptación

- [x] `npm run dev -w @bc/web` levanta la app en el puerto 5173.
- [x] Prueba: el menú muestra las opciones correctas para cada rol.
- [x] Prueba: una ruta protegida sin sesión redirige al login.
- [x] `npm run build -w @bc/web` compila sin errores.

## Verificación

```bash
npm run test -w @bc/web && npm run build -w @bc/web && npm run check
```
