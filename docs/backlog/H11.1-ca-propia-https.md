# H11.1 — CA propia y certificado HTTPS

## Contexto

Diseño §5.11 (Unidad 3: autoridad de certificación y servidor web seguro). Se puede hacer en cualquier momento.

## Archivos

`infra/tls/generar-ca.sh`, `infra/tls/README.md`.

## Especificación

- El script, con `openssl`:
  1. Crea la CA raíz "Blockchain Integridad CA" (EC P-256, 5 años): `secrets/tls/ca.key` y `ca.crt`.
  2. Crea la llave del servidor y un CSR, y emite el certificado de servidor (EC P-256, 397 días) con SAN `DNS:localhost, IP:127.0.0.1`, `extendedKeyUsage=serverAuth` y `basicConstraints=CA:FALSE`.
  3. No sobrescribe nada que ya exista.
  4. Pone permisos 600 a las llaves.
- El README explica cómo confiar en la CA en Linux (`/usr/local/share/ca-certificates` + `update-ca-certificates`), en Chrome/Firefox, y cómo mostrar la cadena de certificados en la sustentación.

## Criterios de aceptación

- [ ] `openssl verify -CAfile secrets/tls/ca.crt secrets/tls/server.crt` → OK.
- [ ] `openssl x509 -in secrets/tls/server.crt -noout -text` muestra el SAN y `CA:FALSE`.
- [ ] Ningún archivo de `secrets/` queda en git (`git status` limpio).

## Verificación

```bash
bash infra/tls/generar-ca.sh && openssl verify -CAfile secrets/tls/ca.crt secrets/tls/server.crt
```
