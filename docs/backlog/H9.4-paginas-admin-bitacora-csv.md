# H9.4 — Páginas Admin, Bitácora, CSV y Exportar

## Contexto

Junta la UI de las APIs de E3, E5, E6 y E7. **Se puede hacer por partes** apenas esté cada API. Si se hace por partes, anota en las notas cuáles están listas.

## Especificación

- **Usuarios** (admin): listar, crear, activar/desactivar y cambiar rol.
- **Llaves** (admin): pendientes con aprobar/rechazar, mostrando la huella SHA-256 de cada llave.
- **Ataques** (admin, solo si la API los expone): catálogo con botón por ataque, selector de índice, "Tomar snapshot", "Restaurar demo" y un atajo "Verificar ahora" que muestra el reporte de H9.3.
- **Bitácora** (admin y auditor): tabla paginada y el estado de integridad de la bitácora.
- **CSV** (registrador, dentro de Personas): subir → ver válidas e inválidas → firmar y anexar.
- **Exportar** (admin y auditor): descargar el JSON, descargar `server-public.pem` y mostrar la huella.

## Criterios de aceptación

- [x] Manual, siguiendo el guion del diseño §9 (pasos 3 a 7), de punta a punta desde la UI.
- [x] Pruebas de render básicas por página, con la API simulada.

## Notas de traspaso

### Decisiones tomadas

- Se hizo completa en un solo PR. Pantallas listas: **Usuarios**, **Llaves**, **Ataques**, **Bitácora**, **Exportar** (más **CSV** dentro de Personas, de H7.1, y Verificar de H9.3). `src/api/admin.ts` agrupa las llamadas.
- **Exportar** pasó a ser visible también para el admin (antes solo el auditor; el diseño dice admin y auditor).
- **Ataques:** si `GET /api/ataques` da 404 (sin `DEMO_MODE`) solo se muestra un aviso, sin controles. «Restaurar demo» pide `window.confirm`. Un único índice de bloque (por defecto 1) sirve para todos los ataques. Muestra `deteccionEsperada` de cada ataque (H10.3 puede darle más presencia).
- **Llaves:** huella SHA-256 con los primeros 32 hex (igual que «Mi llave»), valor completo en el tooltip.
- **Usuarios:** un admin no puede pulsar «Desactivar» sobre sí mismo (el servidor también lo impide). El cambio de rol es un `<select>` por fila que hace PATCH al instante.
- **Descargas:** `solicitarArchivo` conserva el nombre de `Content-Disposition` (solo `[A-Za-z0-9._-]`) y `guardarArchivo` crea el archivo con un Blob; nada se envía a terceros.
- `test/ayudantes.tsx`: `simularApi` acepta `headers` en la respuesta simulada.
- **Manual (criterio):** con API y web reales (BD temporal): Llaves → aprobar la llave de `ana` desde la UI; `ana` firma 3 bloques; Ataques → snapshot → ataque 1 sobre el bloque 2 → Verificar ahora (❌ bloque 2) → Restaurar demo (✅); Bitácora íntegra (14 entradas); Exportar descarga `cadena-AAAAMMDD-HHmm.json` y `server-public.pem` con la huella visible. La generación y el registro de la llave en el navegador (Mi llave) y la creación por formulario están cubiertas por sus pruebas (H5.1, H5.3); aquí la firma de `ana` se hizo por script.
- README y `docs/sustentacion.md` actualizados: la demo ya se hace desde la interfaz.

Sin pendientes.

### Decisiones tomadas

- **Páginas implementadas:** Se implementaron las páginas `Usuarios`, `Llaves`, `Ataques`, `Bitacora` y `Exportar` en `apps/web/src/paginas/` e integradas en `App.tsx`.
- **Usuarios:** Listado completo con estado activo/inactivo, selector interactivo de cambio de rol (`admin`, `registrador`, `auditor`), botón para activar/desactivar y formulario de creación con validación de contraseña mínima de 12 caracteres. Se deshabilita la auto-desactivación para el admin que inició sesión.
- **Llaves:** Consulta de `GET /api/llaves/pendientes`, cálculo de huella SHA-256 del SPKI en el navegador con `huellaSpkiHex`, visualización mediante `<Hash />` y botones de "Aprobar" y "Rechazar".
- **Ataques:** Detecta si la API expone el módulo de ataques (modo demo); si da 404 muestra una alerta informativa amigable (`DEMO_MODE=false`). Si está habilitado, presenta el catálogo con su explicación y detección esperada, selector de bloque objetivo, botón de ejecución por ataque, botones de "Tomar snapshot", "Restaurar demo" y atajo de "Verificar ahora" que reutiliza `<ReporteVerificacion>`.
- **Bitácora:** Paginación accesible con indicador visual del estado de integridad (`verificacion.integra`), hashes de auditoría con soporte para copiar y tooltip.
- **Exportar:** Expuesta para `admin` y `auditor`. Muestra la huella SHA-256 de la clave pública del servidor (`GET /api/cadena/llave-servidor`), descarga directa del archivo `server-public.pem` mediante Blob y descarga del JSON de la cadena con marca de tiempo UTC (`cadena-AAAAMMDD-HHmm.json`), además de instrucciones para verificar con el CLI y enlace al verificador local.
- **CSV:** La carga y firma de lotes CSV ya había sido integrada en la página `Personas` (`CargaCsv.tsx`) durante H7.1.
