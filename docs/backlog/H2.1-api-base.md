# H2.1 — API NestJS base con seguridad por defecto

## Contexto

Diseño §3, §4 "Modelo de datos" y §6. Esqueleto del servicio. Se puede hacer en paralelo con E1.

## Archivos

- `apps/api/**` (reemplaza el README placeholder). Paquete `@bc/api`.
- Si usas `@nestjs/cli new`, **no** crees un repo git anidado (`--skip-git`) y usa npm. Borra lo que no sirva.

## Especificación

- NestJS (última estable) + TypeScript `~6.0` (el de la raíz).
- Prisma + SQLite. `DATABASE_URL` sale de `.env` (ver `.env.example`). Si la versión de Prisma requiere _driver adapter_ para SQLite, úsalo (`@prisma/adapter-better-sqlite3`).
- Esquema inicial:
  ```prisma
  model Persona {
    id                Int     @id @default(autoincrement())
    cedula            String  @unique
    nombre            String
    direccion_cifrada String
    telefono_cifrado  String
    creado_en         String  // ISO UTC con ms, exactamente el que se hasheó
    creado_por        String
    bloque            Bloque?
  }
  model Bloque {
    indice        Int     @id          // 0 = génesis
    persona_id    Int?    @unique
    persona       Persona? @relation(fields: [persona_id], references: [id])
    hash_datos    String
    nonce         Int
    hash_anterior String
    hash_cadena   String
    firma_usuario String?
    llave_id      Int?
    creado_en     String
  }
  ```
- `main.ts`:
  - `ValidationPipe` global con `{ whitelist: true, forbidNonWhitelisted: true, transform: true }`.
  - `helmet()`.
  - CORS solo para `WEB_ORIGIN`, con `credentials: true`.
  - Prefijo global `/api`.
- `@nestjs/throttler` global (p. ej. 100 req/min por IP).
- Filtro global de excepciones: el cliente recibe `{ statusCode, mensaje }` genérico (sin stack). El error completo va al `Logger`.
- `GET /api/salud` → `{ ok: true }`.
- Scripts: `dev` (watch), `build`, `start`, `test` (Jest o Vitest), `typecheck`, `prisma:migrate`.
- `@bc/core` como dependencia (`"@bc/core": "*"`). Antes de `dev`/`build`, `@bc/core` debe estar compilado; agrega `prebuild`/`predev` que lo compile.

## Criterios de aceptación

- [x] `npm run dev -w @bc/api` levanta el servidor y `GET /api/salud` responde 200.
- [x] Prueba e2e: un body con un campo extra en un endpoint de ejemplo con DTO → 400. Se puede usar un DTO de prueba solo en el test.
- [x] Prueba e2e: una excepción no controlada → respuesta sin `stack`.
- [x] La respuesta tiene las cabeceras de helmet (`x-content-type-options: nosniff`).
- [x] La migración inicial existe en `apps/api/prisma/migrations`. La BD queda en `apps/api/data/` (ignorada por git).
- [x] La API importa algo de `@bc/core` (p. ej. `CORE_VERSION` en `/api/salud`) y funciona: esto prueba que CJS↔ESM anda.
- [x] `npm run check` en verde desde la raíz.

## Verificación

```bash
npm run build && npm run test -w @bc/api && npm run check
```

## Fuera de alcance

Endpoints de personas/cadena (H2.2), auth (H3.x).

## Notas de traspaso

### Decisiones tomadas

- **ESM de punta a punta:** NestJS 12 y `@bc/core` son ESM, así que no hay puente CJS↔ESM; `module: NodeNext` e imports locales con `.js`. `/api/salud` devuelve `coreVersion` importado de `@bc/core`.
- **Prisma fijado en 7.x (7.10.1):** el `latest` del paquete `prisma` es un 8.0 rc. Con Prisma 7 hay `prisma.config.ts` (carga `../../.env`, crea `data/`), driver adapter `better-sqlite3` y cliente generado en `apps/api/src/generated/` (ignorado por git; se regenera en `pre*`).
- **Build con `tsc`** (sin `@nestjs/cli`); `dev` compila y luego corre `tsc --watch` + `node --watch`.
- **Vitest con `unplugin-swc`** para emitir los metadatos de decoradores que necesita la inyección de Nest.
- **CORS** con función de origen: solo se refleja `WEB_ORIGIN`; otros orígenes no reciben cabeceras CORS.
- **Filtro de excepciones:** errores `HttpException` devuelven su mensaje (validación unida con `; `); cualquier otro error da `500` genérico y el detalle va al `Logger`.
- **Throttler:** 100 req/min global; las pruebas usan un módulo aparte con límite 2 para comprobar el 429.
- **`npm audit`:** 0 vulnerabilidades en dependencias de runtime. Quedan avisos moderados (`minimatch`) solo en la cadena de ESLint/typescript-eslint (dev); no se forzó el downgrade.
