# H2.3 — Endpoint de verificación

## Contexto

Diseño §4 y §5.8. Implementa el "verificar la integridad calculando los hashes en vivo" del enunciado.

## Especificación

- `GET /api/cadena/verificar` → `ReporteCadena` de `@bc/core`.
- El servicio arma los `BloqueCadena[]` leyendo **la fila actual** de `personas` de cada bloque (join por `persona_id`) y llama a `verificarCadena` con `dificultad = POW_DIFFICULTY`.
- Implementa en `apps/api/src/cripto/verificador-firma.node.ts` un `VerificadorFirma` con `node:crypto`: `crypto.verify('sha256', mensaje, { key: spkiDer, format: 'der', type: 'spki', dsaEncoding: 'ieee-p1363' }, firma)`. Todavía no se pasa: no hay firmas hasta H5.3, pero queda listo y probado con un par de llaves generado en el test.

## Criterios de aceptación

- [x] e2e: cadena recién creada con 3 personas → `valida: true`.
- [x] e2e: modificar `nombre` directamente con Prisma en el test → `valida: false` y `primerBloqueRoto` = el índice de esa persona.
- [x] Prueba unitaria del `VerificadorFirma` de Node: una firma creada con `crypto.sign(..., { dsaEncoding: 'ieee-p1363' })` da true; si se altera, da false.
- [x] El reporte no expone campos internos de Prisma.

## Verificación

```bash
npm run test -w @bc/api && npm run check
```

## Fuera de alcance

Sello y firmas en la verificación (H5.4). Guards (H3.2).

## Notas de traspaso

### Decisiones tomadas

- `CadenaService.verificar()` va por la misma cola que los anexos, así nunca lee una cadena a medio anexar. Lee todo en una sola consulta (`bloque` + `include: persona`).
- El mapeo a `BloqueCadena` es explícito campo a campo, para no exponer `id` ni otros campos internos de Prisma; una prueba comprueba la forma exacta del reporte.
- Sin `verificarFirma` ni sello: firmas y sello salen `no-aplica` hasta H5.3/H5.4. El endpoint es público hasta H3.2.
- `verificarFirmaNode` (`cripto/verificador-firma.node.ts`) devuelve `false` ante llaves o firmas mal formadas, nunca lanza. Está probado con firmas de Node y de WebCrypto (la que hará el navegador). Todavía no se usa.
- Prueba manual: tras alterar un nombre directo en SQLite, el reporte marca `primerBloqueRoto` y motivos en español.
