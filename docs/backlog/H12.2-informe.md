# H12.2 — Informe final

## Contexto

Se hace después del congelamiento de funcionalidades (viernes 20 de noviembre). El proyecto se evalúa con OT1 y OT3.

## Especificación

Documento en `docs/informe/` (o el formato que pida el profesor) con:

1. Problema y enunciado.
2. Arquitectura: un diagrama de componentes y el flujo preparar → firmar → confirmar.
3. **Servicios de seguridad y su justificación criptográfica:**
   - SHA-256: por qué, y la propiedad de resistencia a colisiones.
   - AES-256-GCM: confidencialidad + autenticación del ciphertext.
   - ECDSA P-256: no repudio y sello.
   - argon2id.
   - PoW.
   - PKI propia.
4. Matriz de permisos y su razón: mínimo privilegio y separación de funciones.
5. Lista de codificación segura (diseño §6), cada punto con el archivo donde se aplica.
6. Resultados: tabla de los 5 ataques → qué los detecta (con capturas).
7. **Limitaciones y riesgos aceptados:**
   - _Rollback_ completo de la BD.
   - Confianza en el admin al registrar llaves.
   - Cédula y nombre en claro.
   - Un solo servidor.
   - Hallazgos de `npm audit`, como `minimatch` en las herramientas de lint (solo desarrollo).
8. Consideraciones éticas (OT4): datos personales de terceros y uso responsable del módulo de ataques.

## Criterios de aceptación

- [ ] Cada afirmación de seguridad apunta a código o a una prueba existente.
- [ ] Incluye la salida actual de `npm audit` y cómo se trató cada hallazgo.
